# API SAAP — v1

Superfície REST para o app móvel. **Não há app na v1**: a API existe para o
motor de avaliação nascer com fronteira definida.

Base: `/api/v1` · Autenticação: token pessoal (Laravel Sanctum)

> **A API não reimplementa nada.** Cada endpoint de escrita chama o mesmo caso
> de uso de `app/Application/` que a interface web chama. Nenhuma regra de
> pontuação existe em dois lugares.

## Autenticação

```http
POST /api/v1/auth/login
Content-Type: application/json

{ "email": "ana@clinica.test", "password": "...", "device_name": "iPad da clínica" }
```

```json
{ "token": "1|abc...", "user": { "id": 1, "name": "Dra. Ana", "email": "ana@clinica.test" } }
```

Use em todas as demais chamadas: `Authorization: Bearer {token}`.

Limite: 5 tentativas por minuto no login, 60/min no resto.

| Método | Rota | O que faz |
| --- | --- | --- |
| POST | `/auth/login` | Devolve token pessoal |
| POST | `/auth/logout` | Revoga o token atual |
| GET | `/me` | Perfil e dados da clínica |

## Aprendizes

| Método | Rota | O que faz |
| --- | --- | --- |
| GET | `/learners` | Lista paginada (20/página) |
| POST | `/learners` | Cria |
| GET | `/learners/{id}` | Detalhe com avaliações |
| PUT | `/learners/{id}` | Atualiza |
| GET | `/learners/{id}/assessments` | Avaliações do aprendiz |

Um psicólogo só enxerga os próprios aprendizes — qualquer outro id devolve
**403**, não 404.

**Enviar `photo` exige `image_consent=1`** — sem a atestação de que os
responsáveis assinaram o termo de uso de imagem, a requisição volta 422 com
`image_consent` nos erros. A regra vive no `FormRequest`, que é o mesmo da web:
não há porta dos fundos pela API. `image_consent_at` na resposta diz desde
quando há autorização; enviar `image_consent` ausente numa atualização
**revoga** a autorização e apaga a foto.

## Avaliações

| Método | Rota | O que faz |
| --- | --- | --- |
| POST | `/assessments` | Abre avaliação (`learner_id`, `applied_on` opcional) |
| GET | `/assessments/{id}` | Estado, níveis e progresso |
| POST | `/assessments/{id}/levels/{n}/start` | Inicia o nível |
| GET | `/assessments/{id}/levels/{n}/items` | Marcos do nível + respostas |
| PUT | `/assessments/{id}/responses/{itemId}` | Grava uma resposta |
| POST | `/assessments/{id}/levels/{n}/complete` | Conclui o nível |
| POST | `/assessments/{id}/complete` | Conclui e **trava** a avaliação |
| POST | `/assessments/{id}/cancel` | Cancela (exige `reason`) |
| GET | `/assessments/{id}/report` | Snapshot do laudo |

Níveis são independentes: começar pelo 2 ou pelo 3 é caminho normal.

### Gravação idempotente

```http
PUT /api/v1/assessments/12/responses/34
```

```json
{
  "entries": [
    { "position": 1, "stimulus_id": 12, "is_checked": true },
    { "position": 2, "text_value": "água" }
  ],
  "notes": "criança dispersa hoje",
  "override": { "score": 0.5, "reason": "critério qualitativo" }
}
```

**É idempotente por construção**: o índice único `(assessment_id, item_id)`
faz o `updateOrCreate` convergir. Enviar o mesmo corpo duas vezes produz o
mesmo estado — é o que permite ao app offline esvaziar a fila sem medo depois
de uma queda de rede.

A resposta traz pontuação e progresso já recalculados, para o cliente nunca
duplicar a regra:

```json
{
  "response": {
    "item_id": 34, "score": 0.5, "computed_score": 0.5,
    "is_overridden": false, "answered": true,
    "needs_confirmation": false, "tally": 3
  },
  "progress": {
    "area":       { "answered": 3,  "total": 5 },
    "level":      { "answered": 32, "total": 45 },
    "assessment": { "answered": 78, "total": 170 }
  }
}
```

`needs_confirmation: true` aparece nos marcos de `scoring_mode: assisted` — os
dois critérios pedem a mesma contagem e só a qualidade os separa. O marco fica
salvo mas **não conta como respondido** até vir um `override` explícito.

O denominador de `assessment` é a soma dos níveis **iniciados**, não 170 fixo.

## Catálogo

```http
GET /api/v1/catalog/levels/1
If-None-Match: "a1b2c3..."
```

Devolve áreas, marcos, critérios, listas fixas e URLs dos estímulos. Com
`If-None-Match` atualizado, responde **304**.

Permite ao app baixar o catálogo uma vez e operar sem conexão.

`Cache-Control: private, max-age=86400` — **nunca `public`**: é conteúdo
licenciado do VB-MAPP e não pode ficar em cache compartilhado.

## Erros

Formato único, mensagens em português (vão direto para a interface do app):

```json
{ "message": "Esta avaliação foi concluída e não pode ser alterada.", "code": "assessment_locked" }
```

| Situação | HTTP | `code` |
| --- | --- | --- |
| Sem token ou token inválido | 401 | `unauthenticated` |
| Recurso de outro usuário, ou avaliação travada | 403 | `forbidden` |
| Não encontrado | 404 | `not_found` |
| Validação | 422 | `validation_failed` (+ `errors`) |
| Nível não iniciado | 409 | `level_not_started` |
| Conclusão com nível incompleto | 409 | `level_incomplete` |
| Aprendiz já tem avaliação aberta | 409 | `assessment_already_open` |
| Avaliação já concluída | 409 | `assessment_locked` |
| Avaliação cancelada | 409 | `assessment_cancelled` |
| Excesso de requisições | 429 | `too_many_requests` |

## Fora do escopo da v1

- Upload de foto pela API (o `multipart` funciona, mas não foi exercitado)
- Sincronização em lote (o app deve reenviar item a item — a idempotência
  torna isso seguro)
- Webhooks e paginação por cursor
